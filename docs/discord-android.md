# Discord Rich Presence на Android

## Пользовательские настройки

Для публикации через **свою учётную запись self-host сервера** нажмите «Подключить Discord» в профиле WebUI либо используйте блок «Discord · учётная запись на сервере» в Android. Если администратор установил серверный SDK-мост, приложение само отправляет прослушивание от вашего аккаунта Nami. Для этого пути на телефоне не нужны SDK AAR и Application ID. Настройка администратора, изоляция пользователей и ограничения описаны в [discord-server-oauth.md](discord-server-oauth.md). Ниже описан отдельный прямой Android RPC.

Откройте **Настройки → Плеер → Discord**:

1. Создайте своё приложение в [Discord Developer Portal](https://discord.com/developers/applications).
2. Включите для него Social SDK. Для публикации нужен SDK 1.10+ с поддержкой Android RPC.
3. Скопируйте **Application ID** из General Information в Nami и нажмите «Сохранить ID».
4. Включите «Прямое подключение к Discord на телефоне».
5. Установите Discord на этот телефон, войдите в аккаунт и разрешите показ активности в настройках Discord.

Application ID — публичный идентификатор приложения. Вводить токен Discord-аккаунта, bot token или client secret не нужно. Имя приложения в Discord зависит от приложения, которому принадлежит введённый ID.

Настройка «Показывать совместный режим» добавляет к исполнителю текущий режим:

| Состояние Nami | Надпись |
| --- | --- |
| Обычное воспроизведение | Слушает музыку |
| Подключённый Джем, ведущий | Джем · ведущий |
| Подключённый Джем, участник | Джем · участник |
| Локальное совместное прослушивание, ведущий | Слушать вместе · ведущий |
| Локальное совместное прослушивание, гость | Слушать вместе · гость |
| Активная раздача трека | Раздаёт трек |

При пересечении режимов приоритет: подключённый Джем → гость совместного прослушивания → ведущий → раздача → обычное прослушивание.

Эти функции уже существуют в Nami; интеграция отображает их состояние. Она не создаёт комнат в Discord, не передаёт через Discord аудио и не публикует коды Джема или LAN-адреса.

Пауза, буферизация, остановка, потеря медиасервиса и выключение настройки очищают активность. Перемотка пересчитывает временные метки. Частые изменения объединяются; последнее состояние повторяется для восстановления после перезапуска Discord. Экран настроек показывает подтверждение публикации только после успешного ответа SDK.

## Подключение SDK при сборке

Ввод ID пользователем не устанавливает SDK: нативная библиотека должна быть включена в APK разработчиком.

Официальный SDK скачивается в Developer Portal после включения Social SDK. Бинарные файлы SDK не находятся в этом репозитории. Не заменяйте SDK библиотеками для self-bot или desktop named-pipe RPC.

1. Скачайте официальный Android `discord_partner_sdk.aar` версии **1.10 или новее**.
2. Положите файл в `app/libs/discord_partner_sdk.aar` либо укажите путь в `local.properties`:

   ```properties
   nami.discordSdkAar=C:/SDK/discord_partner_sdk.aar
   ```

3. Установите Android NDK и CMake 3.22+ через SDK Manager.
4. Соберите вариант с обязательной проверкой наличия SDK:

   ```powershell
   .\gradlew.bat :app:assembleDebug -Pnami.requireDiscordSdk=true
   ```

   Путь также можно передать через `-Pnami.discordSdkAar=C:/SDK/discord_partner_sdk.aar`.

Gradle подключает AAR, Prefab и JNI-мост `app/src/main/cpp/discord_presence.cpp`. Вызовы SDK выполняются на главном потоке приложения; SDK инициализируется через текущую Activity, дальнейшие обновления не привязаны к Compose-экрану.

Без AAR собирается development-вариант с доступным вводом ID, но без сетевой публикации. Он явно сообщает об отсутствии поддержки Discord. Такой APK нельзя выдавать за сборку с работающим RPC. Флаг `nami.requireDiscordSdk=true` защищает от случайного выпуска такого варианта.

## Текущие границы

- Реализованы название, исполнитель, тип Listening, временные метки и отображение существующих совместных режимов.
- Обложки локальной библиотеки не загружаются в публичное хранилище. Динамические обложки в этой реализации отсутствуют.
- Приглашения «Присоединиться» через Discord и синхронное прослушивание именно средствами Discord не реализованы; используются существующие функции Nami.
- Self-host публикация при выключенном ПК не входит в этот Android-мост. Android RPC обращается к Discord на том же телефоне.
- Фоновую работу, очистку при принудительном завершении процесса и реальное отображение нужно проверить на устройстве с официальным SDK и Discord. Принудительное завершение Android не гарантирует выполнение cleanup-кода приложения.
- Нативный SDK, собранный APK с SDK и реальная публикация не проверены без официального AAR и настроенного Discord-приложения.

## Проверки

Проверка 2026-09-15: прошли 233 теста (`domain`: 15, `data`: 110, `player`: 108), компиляция Android-кода и `:app:hiltJavaCompileDebug` в development-варианте без SDK. Проверка native-моста и публикации на телефоне остаётся открытой до получения официального AAR.

```powershell
.\gradlew.bat :domain:test :data:testDebugUnitTest :player:testDebugUnitTest :app:hiltJavaCompileDebug
```

`DiscordPresenceTest` проверяет приоритет режимов, скрытие при паузе/остановке, несовпадение очереди и проигрываемого трека, таймер после seek, приватность кодов комнат и валидацию ID. `AppSettingsRepositoryTest` проверяет сохранение пользовательских настроек.

На телефоне дополнительно проверить: разные треки, кириллицу/эмодзи, паузу, перемотку, заблокированный экран, все режимы, смену ID, выключение настройки, перезапуск Discord. Публикацию смотреть также из другого Discord-аккаунта.
