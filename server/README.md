# NAMI server (этап 1)

Self-hosted сервер: библиотека, passthrough-отдача аудио, сопряжение устройств по QR.
Бюджет, под который написано: 1 ядро, 512 МБ RAM, 50 000 треков.

## Запуск

```sh
cp config.example.toml config.toml   # прописать music_dirs
cargo run --release
```

Мастер сопряжения: `https://<адрес>:4533/setup` - показывает QR и восьмизначный код.

## Ручки

| Метод | Путь | Токен | Что делает |
|---|---|---|---|
| GET | `/api/health` | нет | живость, версия, число треков, включён ли TLS |
| POST | `/api/auth/pair` | нет | `{code, device_name}` -> постоянный токен |
| GET | `/setup` | нет | HTML с QR `nami://pair?...` |
| GET | `/api/host-capabilities` | да | измеренные CPU/RAM и пороги тяжёлых фич |
| GET | `/api/tracks?limit&offset` | да | список треков |
| GET | `/api/tracks/{id}` | да | метаданные трека |
| GET | `/api/tracks/{id}/stream` | да | файл байт-в-байт, HTTP Range/206 |
| POST | `/api/scan` | да | пересканировать библиотеку |
| GET | `/api/auth/devices` | да | активные устройства |
| DELETE | `/api/auth/devices/{id}` | да | отозвать токен |

Токен передаётся как `Authorization: Bearer <токен>`.

## Чего ещё нет

- Live-watch папок (inotify) - библиотека обновляется по `POST /api/scan`.
- Внешний доступ (домен, Tailscale, Cloudflare Tunnel) - сейчас только локальная сеть
  с самоподписанным сертификатом, отпечаток которого клиент закрепляет из QR.
- Страница `/setup` открыта всем в локальной сети - закроется вместе с полноценным
  мастером настройки (пароль владельца на первом старте).
- Транскодинг, синхронизация состояния, многопользовательность, лирика, веб-клиент -
  отдельные этапы.
